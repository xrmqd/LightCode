# Ветки и проверка изменений LightCode

`main` содержит одобренный код для выпуска. Рядом с ней ведётся интеграционная
ветка `dev`, в которой собираются изменения перед локальной проверкой.

Рабочий цикл:

1. Создать `feature/<название>` или `fix/<название>` от `dev`.
2. Разработать и проверить изменение в этой ветке.
3. Объединить её в `dev`. Для pull request целевой веткой служит `dev`.
4. Собрать и проверить dev-версию локально на компьютере.
5. После одобрения объединить проверенный `dev` в `main` и отправить `main`
   в GitHub. Этот push запускает полную release-сборку и публикацию релиза.

Пуши в `dev`, `feature/*` и `fix/*` сохраняют код в GitHub и не запускают
облачные сборки. Эти ветки не публикуют пререлизы. Объединение веток
выполняется явно после проверки.

## Локальная разработка

Команды выполняются из корня репозитория. Для сборки понадобятся зависимости
из [инструкции для macOS](./macos.md).

Создать ветку для задачи:

```sh
git switch dev
git switch -c feature/my-feature
```

Собрать и запустить отладочную версию:

```sh
GRAM_RELEASE_CHANNEL=dev cargo run --package gram
```

Собрать `LightCode Dev.app` для Apple Silicon с ad-hoc подписью:

```sh
LIGHTCODE_RELEASE_CHANNEL=dev APPLE_SIGNING_KEY=- ./script/bundle-mac -d aarch64-apple-darwin
```

Приложение находится в
`target/aarch64-apple-darwin/debug/bundle/osx/LightCode Dev.app`. Канал `dev`
сохраняется внутри приложения и при запуске из Finder.

Готовые изменения объединяются обратно в `dev`. Проверенный набор изменений
после одобрения переносится в `main`.

Подробнее об автоматическом выпуске: [Сборки и релизы на GitHub](./github-releases.md).
