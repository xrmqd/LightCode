# Сборки и релизы LightCode на GitHub

Workflow `.github/workflows/ci.yaml` собирает macOS только для Apple Silicon
на стандартном GitHub-hosted runner `macos-26`. Intel временно отключён.
Linux используется только для публикации уже готовых файлов.
Workflow для Codeberg/Forgejo удалены; шаблоны issues сохранены.

## Автоматическая сборка веток

Каждый push запускает сборку соответствующей версии:

| Ветка | Rust-профиль | Приложение | Публикация |
| --- | --- | --- | --- |
| `main` | `release` (`cargo build --release`) | `LightCode.app` в `LightCode.dmg` | Обычный GitHub Release, отмеченный Latest |
| `dev` | `dev` (`cargo build`, папка `debug`) | `LightCode Dev.app` в `LightCode-Dev.zip` | GitHub Prerelease, без отметки Latest |

У каждой сборки свой тег: `v3.5.0+build.12` для `main` и `dev-3.5.0.13` для `dev`.
Версия берётся из `[workspace.package]` в `Cargo.toml`, а номер сборки — из
GitHub Actions. Существующие теги не переносятся на другой коммит.
Повторный запуск той же сборки обновляет её релиз и файлы.

Релиз публикуется после успешной сборки. В нём также находятся
`lightcode-remote-server-macos-aarch64.gz`, `LightCode-source.tar.gz` и
`SHA256SUMS.txt`. Исходники и тег соответствуют точному коммиту собранного приложения.
Статус prerelease задаётся каналом сборки; dev-версии не становятся Latest.

Dev-приложение сохраняет канал `dev` при запуске из Finder и может находиться
рядом со стабильной версией. Архив сохраняет структуру, подпись и разрешения `.app`.

## Ручной запуск и теги

В Actions открой **LightCode macOS builds and releases → Run workflow**.
Запуск на `main` или `dev` использует те же правила, что и push.
На других ветках без поля `tag` файлы сохраняются только в Artifacts на 14 дней.

Поле `tag` принимает существующий тег для повторной сборки. Пуш тегов `v*`
также запускает сборку и публикацию. Теги `dev-*` при ручном запуске дают
отладочную сборку и prerelease; теги `v*` используют release-профиль.
Тег `v*` с дефисом помечается как prerelease.

Используется встроенный `GITHUB_TOKEN`; отдельный PAT не нужен.
Публикующая задача запрашивает `contents: write`. Создание тегов через
`GITHUB_TOKEN` не запускает ещё одну сборку.

Не отправляй все унаследованные теги (`git push --tags`): push-события для `v*`
запустят сборки этих версий.

## Подпись и сборочные инструменты

Сборки имеют ad-hoc подпись (`codesign --sign -`), без Developer ID и notarization.
Сертификаты и аккаунт Apple не требуются. macOS может блокировать первый запуск;
разрешение выдаётся в настройках «Конфиденциальность и безопасность».
Профиль разработчика оригинального Gram в эти сборки не копируется.

На раннере нужны полный Xcode и Metal toolchain. Rust берётся из
`rust-toolchain.toml`, зависимости Cargo фиксируются через `--locked`.
Скрипт упаковки учитывает профиль `debug` и `release`, включая remote-server.

Адрес репозитория и точный тег встраиваются перед компиляцией через
`LIGHTCODE_REPOSITORY_URL` и `LIGHTCODE_RELEASE_TAG`. SSH скачивает сервер
из соответствующего релиза LightCode. Готовые remote-server собираются
только для macOS на Apple Silicon.
