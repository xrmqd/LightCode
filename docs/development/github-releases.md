# Сборки и релизы LightCode на GitHub

Workflow `.github/workflows/ci.yaml` автоматически запускается только при push
в `main`. Он собирает полную release-версию для Apple Silicon на стандартном
GitHub-hosted runner `macos-26` и после успеха публикует обычный GitHub Release.
Intel временно отключён. Linux используется только для публикации готовых файлов.

## Ветки и выпуск

| Ветка | Сборка | Публикация |
| --- | --- | --- |
| `main` | Автоматическая, `cargo build --release` | Обычный релиз с `LightCode.dmg`, отмеченный Latest |
| `dev` | Локальная проверка интегрированных изменений | Облачная сборка и пререлиз не запускаются |
| `feature/*`, `fix/*` | Локальная разработка от `dev` | Облачная сборка и публикация не запускаются |

Изменения объединяются из рабочих веток в `dev`, проверяются локально и после
одобрения переносятся в `main`. Схема и команды описаны в
[правилах ветвления](./branching.md).

Релиз содержит `LightCode.dmg` с `LightCode.app`, соответствующий
`lightcode-remote-server-macos-aarch64.gz`, `LightCode-source.tar.gz` и
`SHA256SUMS.txt`. Исходники и тег относятся к точному коммиту собранного приложения.

Каждый выпуск получает тег вида `v3.5.0+build.12`. Версия берётся из
`[workspace.package]` в `Cargo.toml`, номер сборки — из GitHub Actions.
Существующие теги не переносятся на другой коммит. Повторный запуск того же
workflow обновляет его релиз и файлы.

## Ручной запуск

В Actions открой **LightCode macOS builds and releases → Run workflow** и
выбери `main`. Запустится та же production-сборка и публикация, что и при push.
Для повторения старой сборки используй её **Re-run jobs**.

Ручной запуск на других ветках пропускает сборочные задачи. Пуш тегов сам по
себе сборку не запускает. Dev-версии собираются локально.

Используется встроенный `GITHUB_TOKEN`; отдельный PAT не нужен.
Публикующая задача запрашивает `contents: write`. Файлы также сохраняются
в Artifacts на 14 дней в архиве `macos-aarch64`.

## Подпись и сборочные инструменты

Сборки имеют ad-hoc подпись (`codesign --sign -`), без Developer ID и notarization.
Сертификаты и аккаунт Apple не требуются. macOS может блокировать первый запуск;
разрешение выдаётся в настройках «Конфиденциальность и безопасность».
Профиль разработчика оригинального Gram в эти сборки не копируется.

На раннере нужны полный Xcode и Metal toolchain. Rust берётся из
`rust-toolchain.toml`, зависимости Cargo фиксируются через `--locked`.
Workflow для Codeberg/Forgejo удалены; шаблоны issues сохранены.

Адрес репозитория и точный тег встраиваются перед компиляцией через
`LIGHTCODE_REPOSITORY_URL` и `LIGHTCODE_RELEASE_TAG`. SSH скачивает сервер
из соответствующего релиза LightCode. Готовые remote-server собираются
только для macOS на Apple Silicon.
